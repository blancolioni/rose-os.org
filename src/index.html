Persistent · Capability-based · Written in Ada

Rose

An operating system where holding a capability is the only way to do anything.

Rose is a small kernel and a set of user-space servers. Every process acts only through the capabilities it holds, and the system is built to keep its state across restarts. It runs on i686 under QEMU, boots to the Petal shell, and is very much a work in progress.

How it works

Three ideas

Authority

Capabilities

A process can do only what its capabilities allow, and holding one is all it needs. To the process a capability is just a 32-bit word. The kernel uses it to find a structure that names an object and the rights the holder has over it. There is no global namespace to go looking in.

State

Persistence

Rose is designed to keep running across restarts. Checkpoints save the system's page objects to disk, and a restore brings back the latest consistent one, with processes keeping the capabilities they held. The checkpoint and restore servers exist; restoring every process is still being built.

Contracts

Interfaces

Every interface between processes is declared in an interface definition language that reads like an Ada package spec. The IDL compiler, idle, generates the Ada client and server packages from it, so both sides of a call agree by construction.

Inside the kernel

Anatomy of a capability

Behind each capability word is a 16-byte structure in the kernel. This is the generic layout; the diagram in the Rose Book is generated from the same description, and the build checks it against the Ada record.

31 8 7654 3 0
+0 Rescinded Count XWRS Type
+4 Identifier Endpoint
+8 Payload (64 bits), often an object id
Type
What the capability names: a page object, a process, an endpoint, a set, a kernel service.
S R W X
Single use, and read, write and execute access to the resource.
Rescinded Count
How often the capability has been rescinded. It must match whenever the capability is invoked.
Endpoint
Which of the receiving object's endpoints the invocation reaches.
Identifier
A value handed to the receiving object, so it can tell its callers apart.
Payload
Type-specific data, usually the object id.
